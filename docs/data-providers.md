# 데이터 연결 시연과 실제 API 교체

현재 네트워크 API는 연결하지 않습니다. 화면의 네 제공자는 기존 시연 카탈로그를 기반으로 각 1~2건을 만들며, 실제 기관의 응답·공식 가격·공급 경보라고 표시하지 않습니다.

| 영역 | 현재 시연 | 실제 연결 대상 |
|---|---|---|
| 레시피·재료 | 선택일 국·메인 두 메뉴의 1인분 재료량을 95% 예시로 변경 | [식약처 COOKRCP01](https://www.foodsafetykorea.go.kr/api/openApiInfo.do?menu_grp=MENU_GRP31&menu_no=661&show_cnt=10&start_idx=1&svc_no=COOKRCP01), [농식품 재료정보](https://www.data.go.kr/data/15058981/openapi.do) |
| 영양 | 해당 메뉴 재료 두 품목의 기존 시연 영양값 | [식품영양성분 DB](https://various.foodsafetykorea.go.kr/nutrient/) |
| 가격 | 두 품목에 32%·24% 상승 시나리오와 1~4주 비교값 | [KAMIS 일별 가격·최근 가격추이](https://www.kamis.or.kr/customer/reference/openapi_list.do) |
| 공급 | 두 품목의 선택일 중간 수준 입고 지연 시나리오 | 추후 승인된 공식 공급위험 자료 |

선택일 화면에서 적용한 자료는 해당 날짜의 입력 버전에 저장됩니다. 서버가 조리·재료·위험·권고를 다시 계산하며, 원래 재고·원본 모델 예측은 유지합니다. 레시피·영양 시연을 적용하면 해당 한 끼의 원재료별 기준 g을 영양 DB 기준량으로 환산하여 단백질·열량·나트륨을 합산합니다. 필요한 자료가 빠졌으면 0으로 채우지 않고 미확인 상태로 둡니다. 선택을 해제하고 적용하면 기존 자료를 사용합니다. 메뉴를 바꾸면 이전 메뉴에 적용한 시연 패치는 해제됩니다.

실제 연결 시 서버 전용 인증키를 사용하고 기관별 원문을 `recipes`, `nutrition`, `prices`, `supply_events` 계약으로 검증·변환해야 합니다. COOKRCP01의 재료 설명 문자열을 무조건 수치화하지 않으며 인분·g/kg·품종·부위·생것/조리 상태를 확인합니다. 가격 API의 포장 단위를 kg 단가로 오인하지 않습니다. 외부 호출 실패 시 마지막 검증된 자료를 보존하고 실패를 알려야 합니다. 키를 등록하는 것만으로 현재 시연 제공자가 실제 API로 전환되지는 않습니다.

## 확정 기록

날짜별 `diners`는 운영자가 정한 식수이며 모델 예측과 별개로 보존됩니다. Operation Agent가 안전 여유·올림·재료량을 계산합니다. 확정 API는 최신 날짜 버전·계산 완료·저장 완료·차단 여부·용량을 확인하고 `api_plan_confirmations`에 인원·조리량·시각을 저장합니다. 같은 확정 요청은 중복 기록하지 않습니다. 원본 Agent 결과는 변경하지 않습니다.

자료·메뉴·식수 변경 시 예전 확정 기록은 감사 이력으로 남고, 현재 확정 표시가 해제됩니다. 재계산 후 다시 확정해야 합니다. 시연 확정은 실제 데이터 검증이나 자동 발주를 의미하지 않습니다.
