# LastPlate UI/UX 개편 결과 · 1.1.0
작성일: 2026-09-18

사용자 제공 「실제 화면 UI/UX 점검 및 3단 IA 개편안」에 따라 업무 화면과 개발자 진단을 분리했습니다.
기존 네 Agent 내부와 모델, lastplate_db 모듈을 수정하지 않고 API·저장 어댑터·화면을 변경했습니다.

## 바뀐 사용 흐름
사업장·운영일 선택 → 계획 생성 → 플래너에서 상태·재료·위험 검토 → 변경사항 해석과 재계산 → 현장 결과 저장·정정.
생성 후 플래너 제목에 초점을 이동하며 저장 계획을 URL과 선택 목록으로 복구합니다.
모델 원본 예측 / 운영 조정 기준 / 검토용 조리량은 분리됩니다. 열람 확인은 승인으로 바뀌지 않습니다.

## 실제 검증
- 새 업무 API/정정/재시도/인증/설정 10개, 기존 공개 API 24개, 경계 9개, DB 회귀 250개: 합계 293개 통과했습니다.
- 실제 Edge 브라우저, 실제 모델과 네 Agent, 독립 SQLite로 업무 동선 19개를 검증했습니다.
- 사업장 전환 후 식수·조리량·폐기·비고·저장 요약 잔존 없음.
- 2026-09-19 기본: 원본 예측 1,111명, 검토용 1,145식.
- 방문 인원 +80명: 원본 1,111명 유지, 운영 기준 1,191명, 검토용 1,227식(+82식).
- 실제 1,180명 입력: 모델 원본 대비 +69명, 운영 기준 대비 -11명, 초과 조리 47식.
- 1,181명으로 정정: 비교값 +70명/-10명, 기존 1,180명은 감사 이력에 보존.
- 재고 위험: 두부 91.6kg 필요 / 기록 재고 38kg / 추가 확보 검토 53.6kg, 차단 유지.
- 소규모 사업장: 원본 예측 보존, 적용 범위 경고와 인원 확인 동선.
- 강제 DB 저장 실패: 계산값 화면 유지, 같은 계획 ID로 저장 재시도, 재추론 없음.
- 실제 서버를 종료하고 포트가 닫힌 뒤 새 PID로 재시작하여 영속성 확인.
- 일반 화면의 pre/JSON 편집·UUID·원문 상태 없음. 브라우저 JS/콘솔 오류 없음.
- 최종 수치·실행 로그: reports/ux-v2/browser-ux.json, reports/regression/summary.json.
- 화면 증빙: reports/ux-v2/의 PC·모바일 PNG.

## API 접근 변경
기존 통합 API의 데이터 구조는 유지하며 접근 제어를 추가했습니다.
원문 /api/*, /debug, /admin, /docs는 서버 개발 모드와 HTTP Basic 인증이 필요합니다.
기본 업무 화면은 /api/ui/*를 사용하므로 별도 인증 입력 없이 현재 로컬 앱처럼 동작합니다.
개발 도구 활성화와 비밀번호 지정은 README를 참조하세요.
인증 처리는 [FastAPI 공식 HTTP Basic 문서](https://fastapi.tiangolo.com/advanced/security/http-basic-auth/)의 의존성·인증 응답 방식으로 구현했습니다.

## 보존 및 적용
기존 데이터는 새 UI에서 그대로 조회합니다. 새 결과는 선택한 계획에 명시적으로 연결하며, 과거 기록은 저장 당시 예측 기준으로 조회합니다.
설정 수정은 이후 새로 준비하는 계획에 적용됩니다. 기존 계획 스냅샷을 소급해서 바꾸지 않습니다.
바탕화면 적용 전 기존 코드와 DB를 작업 폴더에 백업하고, DB 내용이 유지되는지 비교합니다.
배포 ZIP에는 사용자 DB·가상환경·임시 테스트 DB를 포함하지 않습니다.

## 남는 MVP 범위
자동 발주·메뉴 적용·계획 확정·재학습·근거 없는 절감률은 제공하지 않습니다.
레시피·가격의 신규 데이터 공급 연결, 업무 사용자별 권한 관리, 외부 서비스 배포는 별도 작업입니다.
운영 설정은 현재 로컬 관리자/개발자 공용 인증으로 관리합니다.
DB에 전체 계획 이력까지 저장하지 못한 경우의 재시도 자료는 단일 서버 메모리의 최근 30건입니다.
그 상태에서 서버까지 종료하면 새 계획 계산이 필요합니다.
