# UI · ML · Operation 통합 메모

## 구현 범위

팀원 code.html의 색상·네비게이션·4개 화면 구성은 유지했습니다. 기존 인라인 시연 계산을
frontend/app.js의 API 호출로 바꿨습니다. 단일 FastAPI 서버가 UI와 API를 함께 제공하므로
프런트엔드용 Node 서버나 CORS 설정 없이 실행할 수 있습니다. 원본 code.html, engine.py,
LastPlate-ML-v2.zip은 변경하지 않았습니다.

기존 Streamlit 프로젝트와 **동일한 페이지로 합친 것은 아닙니다**. 새 frontend/backend를
추가하는 독립 실행 경로이며, 기존 app.py·graph.py·tools/*는 그대로 둡니다.

## 주요 수정

| 항목 | 연결 방식 |
| --- | --- |
| 고정 예측 480명 | 시연 입력으로 명시; ML 실행 버튼은 실제 첨부 LightGBM 호출 |
| P95 / 부족 확률 | 실제 모델이 제공하지 않아 삭제. 점 예측 + 별도 안전여유 표시 |
| 인원 변동 | 확정 이벤트만 반영, 취소·ID 중복 방지, 변경 시 새 운영안 이력 |
| 적용 조리량 | 권장량과 수동 적용량 구분. 변동 입력 시 수동값 해제 후 재권장 |
| 재고 | net available 또는 실물−예약 또는 lot 목록 중 하나만 입력 |
| 기한순 배정 | 식사일 이전 만료 lot 제외, 남은 lot을 기한순 배정 |
| 발주 | 설비로 가능한 수량의 부족분을 포장 단위 올림 |
| 납기 | 새 발주 납기가 현재 시각 이후이면서 필요 조리시각 이하여야 입고 가정에 포함 |
| 검토 완료 | 검토 가능 여부를 서버에서도 검사. SQLite에 시연 상태만 저장 |
| 급식톡 | 계산 결과에 근거한 정형 답변. 외부 문서·LLM 검색 아님 |

현재 재고와 새 발주 입고 가정 결과를 혼동하지 않도록 result / projected_after_purchase를 분리했습니다.
발주 추천은 예약·구매·입고 사실이 아닙니다. 동시 요청으로 오래된 운영안을 수정하면 409를 반환합니다.
새 ML 입력 또는 운영 설정 변경은 새 기준 운영안을 만들며, 이벤트/수동 조정은 부모 ID를 가진 revision입니다.

## 모델 선택과 동일성

- 원본 current.json 선택: v20260917T054002-4222a35a / feature group C / LightGBM 4.7.0.
- 정원·휴가·출장·재택·시간외근무, 요일 one-hot 7개, 메뉴 regex 6개: 총 18개 feature.
- 버전명 v2는 전체 패키지 버전입니다. 선택된 모델의 메뉴 규칙은 **v1**을 그대로 사용합니다.
- 날씨는 사용하지 않습니다. 시간외근무는 출근인원에서 빼지 않습니다.
- pickle을 실행하지 않고 pickletools로 내부 native tree 문자열을 추출했습니다.
  실행 시 native_sha256 및 feature 순서를 검사합니다. 추론 결과의 음수 보정 및 반올림도 원본과 같습니다.
- 첨부 inference_smoke의 과거 입력은 **1,034명**으로 동일합니다. 이는 추론 동일성 확인이지 정확도 검증이 아닙니다.
- metadata의 평가 수치는 별도 train+validation 모델의 테스트 결과입니다. 전체 기간으로 재학습된
  현재 배포 모델 자체의 독립 검증 점수로 인용하지 마세요.
- 학습 종료일 2021-01-26. 2026년 사업장의 변화·작은 정원·다른 메뉴에 대한 성능은 검증되지 않았습니다.
- 원본 학습 데이터와 전체 실험 파일은 통합 ZIP/Git 복사 대상에서 제외했습니다.

## 시연 순서

1. 초기화 → 권장 510식, 돼지고기 가용 45kg, 필요 61.2kg, 부족 16.2kg, 발주 20kg(4포장).
2. 출장 -35명 추가 → 변동 후 식수 445명, 권장 480식, 돼지고기 발주 15kg(3포장).
3. 이벤트 취소 → 권장 510식으로 복원.
4. 한도 500 시나리오 → 용량 부족, 검토 완료 제한.
5. 납기 12시 시나리오 → 조리 시작 10시보다 늦어 입고 가정 제외, 검토 완료 제한.
6. 운영 기준 누락 → 검토 완료 제한.
7. 정상 시나리오에서 실제 ML 버튼 → 점 예측 표시, 적용 범위 밖 경고 확인.
8. API로 여러 배치를 넣으면 이미 시작된 1차는 잠그고 시작 전 2차만 증감합니다.
   화면의 기본 예시는 메뉴당 1개 배치입니다. 10시 이후로 시계를 이동하면 그 배치가 잠깁니다.

## 인수인계 / 다음 단계

- UI 팀: frontend/app.js의 api 함수와 docs/api-contract.md를 연결 기준으로 사용.
- ML 팀: 모델 업데이트 시 feature schema/규칙 버전/해시/스모크 입력을 함께 전달.
  현재 import 스크립트는 제공된 ZIP 구조와 C/v1 모델 전용입니다. 다른 모델에 그대로 사용하지 마세요.
- 운영 담당: 사업장 레시피·재고·시작 실적·납기·최소 제공량·영양 기준을 API 입력으로 공급.
- 잠긴 배치가 이미 사용했거나 확보한 재고는 입력 가용량에서 제외해야 합니다.
  실물 입력에 예약량을 넣거나 net available로 보내되 두 번 빼지 마세요.
- FEFO는 식사일까지 유효하다고 입력된 재고의 배정 순서입니다. 식품 안전 판정 자체를 대체하지 않습니다.
- 이벤트는 ML 기준 입력에 포함되지 않은 추가 변동만 넣어야 합니다. 자동 HR/행사 ID 매핑은 아직 없습니다.
- 운영화 전 인증/권한, 실재고 예약 트랜잭션, 발주 승인권자, 입력 확보시각 검증, 재학습/모니터링 필요.
